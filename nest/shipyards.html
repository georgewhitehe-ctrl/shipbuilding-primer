口径说明：本文将“江门南洋船厂”暂按江门市南洋船舶工程有限公司理解。由于船厂的软件资产、接口架构、生产节拍和经营数据通常不公开，本文把内容分为：公开业务特征、基于船舶制造规律的高可信判断、需要访谈或现场核实的假设。文中出现的软件品牌，除非另有明确证据，均表示可能使用或需要兼容的行业候选产品，不代表已经确认装机。

1. 总体判断

1.1 三家船厂不是同一种数字化客户

沪东中华和江南造船同属大型复杂船舶总装建造企业，已经具备较完整的信息化基础。它们面临的主要问题通常不是“有没有软件”，而是已有CAD、生产设计、PLM、ERP、MES、仓储、质量和设备系统之间能否形成可信的数据主线。此类船厂的项目难点集中在旧系统兼容、集团标准、跨专业协同、海量数据、生产不中断和系统安全。

江门南洋更可能代表中型民营或地方商船建造企业。它可能拥有成熟的现场工艺和核心生产设备，但数字化投入、专业IT团队和系统治理能力通常不及大型央企船厂。此类企业更看重部署速度、操作简单、投资回收期和对现有二维图纸、Excel及设备软件的兼容。

因此，同一个“智能套料与生产准备平台”不能用相同方式销售和实施：

1.2 成熟度不能只看是否部署MES

判断船厂数字化成熟度，应检查五条链是否真正闭环：

  1. 设计链：三维模型、二维图、BOM、材料和版本是否一致。
  2. 工艺链：分段、托盘、套料、坡口、焊接和质量要求是否结构化表达。
  3. 计划链：主计划、分段计划、车间计划与设备任务是否联动。
  4. 实物流：钢板、余料、切割件、托盘和分段是否可追踪。
  5. 反馈链：设备实绩、质量结果和现场变更是否回写设计和计划系统。

即使船厂拥有PLM、ERP和MES，只要设计变更仍靠邮件通知、NC程序仍用共享文件夹下发、余料仍靠人工丈量、现场返工没有结构化原因码，就不能认为实现了真正的数字化闭环。

1.3 建议的调研结论级别

  • A级，已证实：船厂官网、正式新闻、招投标公告、供应商案例或论文明确说明。
  • B级，高可信判断：由船型、集团体系、生产基地和行业惯例可以合理推断。
  • C级，待验证假设：具体软件品牌、版本、接口方式、指标和现场操作方式。

后续正式报告应为每一项事实附级别，避免将“行业主流”误写成“该厂正在使用”。

2. 三家船厂共同的生产制造流程

2.1 合同、总体与基本设计

船东需求首先被转化为技术规格书，涵盖航速、载重、舱容、续航、能耗、船级、旗国、排放和设备品牌要求。总体设计阶段完成线型、总布置、稳性、阻力推进、结构强度、舱容和重量重心分析，并与船东、船级社持续迭代。

主要数据包括船型主尺度、舱室、系统原理图、设备清单、结构规范和初步BOM。该阶段的错误会在后续造成大范围返工，因此重点不是套料，而是配置、版本、规则审查和跨专业碰撞。

2.2 详细设计与生产设计

详细设计将总体方案细化为船体结构、管路、电气、电缆、设备、通风和舾装模型。生产设计进一步把模型转化为船厂可以建造的对象：分段、组件、零件、托盘、施工图、材料清单和加工信息。

这里是设计数据进入生产的关键转换点。一个船体零件不仅包含二维轮廓，还可能包含：

  • 船号、分段号、组件号和零件号；
  • 材质、板厚、数量和材料炉批要求；
  • 左右舷、艏艉方向和是否允许镜像；
  • 坡口类型、角度、钝边和加工面；
  • 划线、喷码、装配基准和余量；
  • 船级社检验、无损检测和质量等级；
  • 设计版本、生效日期和替代关系。

若中间格式只传递DXF轮廓，以上属性就会丢失，后续只能靠人工补录。

2.3 采购、钢材入库和预处理

ERP根据BOM和项目计划生成采购需求。钢板到厂后需要核对材质、规格、炉批、船级社证书和表面状态，再完成入库、堆位分配、抛丸和底漆预处理。

关键问题是“系统中的一块板”和“现场的一块板”必须保持一致。若钢板被换位、截短、锈蚀或跨项目借用，库存记录没有同步，套料系统即使算法正确也会生成无法执行的方案。

2.4 钢料准备、零件展开和套料

生产设计输出的零件按材质、板厚、船号、分段、交付时间和设备能力分组。套料工程师选择标准板或余料，设置方向、间距、坡口、割缝、共边、桥接、引入引出和切割顺序，生成套料图、材料清单和NC程序。

这个环节存在四类目标：

  1. 材料目标：提高利用率、减少完整板使用、复用余料。
  2. 交付目标：保证同一分段或托盘及时齐套。
  3. 设备目标：匹配幅面、板厚、切割方式和负荷。
  4. 工艺目标：控制坡口、穿孔、热变形和切割质量。

只优化材料利用率可能造成某分段缺少少数关键件，反而拖延总组节点。

2.5 NC切割、标识和分拣

钢板经上料后进入火焰、等离子或激光切割设备。设备执行NC程序，同时完成或配合喷码、划线和零件标识。切割后，零件需要打磨、检查、分拣并按托盘配送。

现场常见断点包括：设备端仍保留旧程序；操作者临时修改参数但未回传；喷码模糊；零件切下后失去身份；套料图上的余料与实际轮廓不一致；切割完成只记录“已完成”，没有记录实际工时、报警和废品。

2.6 成形、组立和分段建造

平面零件经过折弯、辊弯或水火弯板后进入小组立、中组立和分段装焊。分段内部还要进行管系、电缆、设备和舾装件预装。质量控制覆盖尺寸精度、焊缝、材料、无损检测和密性试验。

套料阶段的方向、坡口和余量错误，通常在这一阶段才暴露，此时纠正成本已经明显上升。小零件缺失也可能导致整个托盘无法开工。

2.7 总组、搭载、调试和交付

分段形成总段后进入船坞或船台搭载。船体成形后继续完成管路、电气、设备、涂装和舾装，随后开展码头调试、系泊试验、航行试验、船级社检验和交付。

这一阶段距离套料较远，但其质量问题往往能追溯到早期数据。例如设备底座孔位不符，可能源于模型版本、加工图、切割程序或现场安装基准不一致。

3. 沪东中华：复杂LNG船场景

3.1 生产制造特征

沪东中华的核心能力与大型LNG运输船、高端液化气船和大型集装箱船紧密相关。LNG船并不是普通船体增加几个液货舱，其设计与建造还涉及低温材料、围护系统、液货管路、绝缘、洁净度、焊接、密性和大量专项检验。

长兴基地扩大生产能力后，管理对象从单个项目进一步扩展为多个大型项目、多个区域和多条产线的协同。由此产生三类复杂性：

  • 产品复杂性：专业多、材料多、质量规则多。
  • 组织复杂性：设计、采购、生产、供应商和船级社共同参与。
  • 规模复杂性：多船并行、海量零件和频繁计划调整。

3.2 生产流程中的重点控制点

  1. 设计冻结与变更：LNG专项设备、管路和围护系统的接口必须严格管理。局部变更可能影响多个专业。
  2. 材料证书：低温钢、不锈钢和特殊材料需要与炉批、证书、零件和焊缝关联。
  3. 坡口与焊接方向：零件旋转或镜像时，坡口面和装配方向必须同步变化。
  4. 分段完整性：结构件与预舾装件需要按计划齐套，避免在后续阶段补装。
  5. 检验记录：制造记录需支持船级社和船东审查，并能够追溯到实物。

3.4 现有痛点的详细推演

痛点一：同一对象存在多个身份。 设计系统中的零件、ERP中的物料、MES中的工单、套料系统中的图形和设备端的NC文件可能通过不同编码关联。映射表一旦由人工维护，设计变更和拆分合并就容易造成错配。

痛点二：变更状态难以跨系统判断。 PLM可以知道零件升版，但未必立即知道该零件是否已经采购、套料、切割、分拣或装配。没有制造状态，变更影响分析只能依赖多人会签。

痛点三：专项工艺知识分散。 LNG船的材料、坡口、焊接和检验规则可能分散在工艺文件、软件参数和专家经验中。新人难以判断自动生成的方案是否真正可制造。

痛点四：局部优化与项目节点冲突。 套料系统可能倾向凑满一张板，但生产计划需要先保证某个关键分段齐套。材料最优和进度最优经常不是同一方案。

痛点五：新基地与历史资产共存。 新设备、新系统和新标准需要兼容历史船型、旧数据、旧程序及既有供应商接口，完全推倒重来风险极高。

3.5 需求与解决方案

  • 建立统一对象ID及跨系统映射服务，使零件、钢板、套料方案、NC、托盘和质量记录可双向追溯。
  • 建立变更影响引擎，根据制造状态自动区分“未套料、已套料未切割、已切割未装配、已装配”并触发不同处理流程。
  • 建立LNG船工艺规则库，将特殊材料、坡口、方向、洁净和检验规则转化为机器可校验条件。
  • 开发多目标动态套料，在材料利用率之外加入分段齐套率、交付优先级、设备负荷、热影响和余料价值。
  • 对NC程序实施受控发布、电子签审、版本锁定和设备端防错；临时修改必须记录并回传。
  • 先以一个船型、一个分段族和一条切割线开展并行验证，避免直接替换全厂系统。

4. 江南造船：多船型与全局协同场景

4.1 生产制造特征

江南造船的突出特点是产品类型和工程任务多样。不同船型在结构、材料、舱室、设备、规范和建造策略上差异明显。同一时期多个项目并行，使钢料加工、分段场地、吊车、船坞和关键班组成为共享资源。

因此，江南造船的核心数字化问题更接近“如何在多船型、多项目和多资源条件下保持全局最优”，而不是只优化一个设计专业或一台设备。

4.2 生产流程中的重点控制点

  • 不同船型的生产设计标准、命名规则和工艺模板需要统一管理又允许差异化配置。
  • 主计划、搭载计划、分段计划、托盘计划和车间任务之间需要逐层分解并动态调整。
  • 钢板、型材、管子和舾装件的加工计划需要围绕分段齐套组织。
  • 设备、场地和吊装资源冲突必须提前识别。
  • 历史项目的工时、质量和异常数据需要反馈到新项目估算。

4.3 软件体系与集成重点

江南造船可能拥有与大型船厂相似的总体设计、生产设计、PLM、ERP、MES和设备系统。真正需要确认的不是“有没有”，而是以下接口是否闭环：

  1. 设计BOM能否稳定转化为制造BOM和托盘清单。
  2. 计划优先级能否实时传入套料、管子加工和设备任务。
  3. 套料结果能否回写材料消耗、余料和预计工时。
  4. 设备是否返回实际开始、结束、报警、暂停和质量结果。
  5. 现场偏差是否形成标准原因码并反馈给工艺和设计。

4.4 现有痛点的详细推演

多船型规则碎片化。 规则可能以设计手册、工艺卡、模板和人员经验存在。系统升级或人员变化后，规则一致性难以保证。

计划层级脱节。 年度与项目计划可以在管理系统中形成，但到车间周计划和设备日任务时，常需大量人工协调。插单、缺料和设备故障会使原计划迅速失效。

材料利用率掩盖齐套问题。 一张板利用率提高1%，如果把不同分段的零件混排并增加分拣、堆放和缺件等待，总成本未必下降。

现场数据粒度不足。 仅记录工序完成，无法区分等待材料、等待图纸、设备故障、质量返工和人员不足，后续优化缺少可靠样本。

经验复用困难。 同类船型的工时、余量、变形和返工问题没有与具体结构特征关联，新项目仍可能重复发生。

4.5 需求与解决方案

  • 建设可配置的船型与工艺规则平台，规则带版本、生效范围、审批人和验证案例。
  • 将套料优化升级为“材料—齐套—设备—物流”联合优化，输出多套可解释方案供计划人员选择。
  • 建立事件驱动的滚动排程：缺料、设备停机、设计升版或节点变化后，只重算受影响范围。
  • 采集设备和工位实绩，将等待、加工、返工和搬运时间分开记录。
  • 建立历史项目知识库，把问题与船型、结构区域、材料、设备和工艺参数关联。
  • 用数字孪生服务于计划验证和物流仿真，避免只做三维展示。

5. 江门南洋：轻量化改造场景

5.1 主体与业务边界需先确认

正式调研前应确认企业完整工商名称、厂区、主要船型、年产能力、是否自有设计院、主要切割设备以及是否存在关联企业。中型船厂公开资料较少，企业简称很容易指向不同主体。

若该企业以中型常规商船建造为主，其竞争重点通常是价格、交付周期、质量稳定和现金流。数字化项目只有快速减少材料浪费、人工录入、找件时间或延期风险，才容易获得持续投入。

5.2 可能的实际流程

设计数据可能来自自有设计部门、外部设计院或成熟母型。生产部门接收二维图、三维模型、BOM和修改通知，再由工艺人员完成分段、零件、套料和施工文件。采购与库存通过ERP、进销存或Excel管理，车间计划可能通过表格、会议和即时通讯协调。

钢料加工环节往往是最适合切入的数字化场景，因为输入和输出相对清晰：输入是零件、材料和钢板，输出是NC、零件、余料与工时。

5.3 可能的软件组合

  • AutoCAD、中望CAD、CAXA或其他二维工具处理图纸。
  • 外部船舶设计系统提供的模型、图纸和BOM。
  • FastCAM、ProNest、SigmaNEST、Lantek、国产套料软件或设备自带CAM中的一种或多种。
  • 通用ERP、财务进销存或定制管理系统。
  • Excel、共享文件夹和企业即时通讯承担计划与协作。
  • 切割、折弯、型材和焊接设备各自带有独立控制软件。

以上均为候选范围。现场应直接查看软件界面、许可证、导入导出文件和设备控制器，不能只询问管理人员“是否有MES”。

5.4 现有痛点的详细推演

文件来源不统一。 同一项目可能同时存在PDF、DWG/DXF、Excel清单和设备程序，版本信息依靠文件名表达。

变更回收困难。 新图发出后，旧图和旧NC仍可能保存在个人电脑、共享目录或设备端。

库存账实不一致。 钢板被临时挪用、余料未登记、现场测量不准确，导致系统推荐的材料实际不可用。

人工准备工作量大。 工艺人员需要重复录入板厚、材质、数量、分段和设备参数，自动套料后仍需大量拖动调整。

零件切割后失去身份。 喷码或标签不稳定，分拣依赖熟练工，后续组立出现找件和错件。

设备信息孤岛。 设备能加工，但运行时间、报警、耗材和程序版本不进入管理系统。

大型系统负担过重。 一次性部署PLM、MES和WMS会带来高实施成本、流程重构和人员抵触。

5.5 分阶段解决方案

第一阶段，8至12周：钢料与程序受控。 建立钢板、余料、零件、套料方案和NC的轻量数据库；统一命名和版本；在一台主力切割设备试点。

第二阶段，3至6个月：实物追踪。 给钢板、余料、零件和托盘配置二维码；移动端完成领料、切割、分拣、入托和异常报工。

第三阶段，6至12个月：计划与设备闭环。 接入ERP库存和主要设备状态，建立工序进度、质量和设备实绩看板。

第四阶段：算法优化。 在数据可靠后实施余料优先、动态套料、齐套分析和设备负荷优化。若跳过数据治理直接上AI，算法会被错误库存和错误版本拖垮。

6. 共同痛点、需求和潜在解决方案

6.1 统一数据模型

共同问题是同一对象在不同系统中有不同名称和结构。解决方案不是简单建立一张映射表，而是定义船舶制造主对象：项目、船号、分段、托盘、零件、材料、钢板、余料、套料方案、NC程序、设备、工序和质量记录。

每个对象需要唯一ID、业务编码、版本、状态、来源系统和关联关系。系统间传递数据时，还要记录谁在何时用哪个版本生成了什么结果。

6.2 设计变更闭环

设计变更应自动完成五步：识别变化内容；定位受影响对象；查询制造状态；选择处置策略；记录执行结果。

例如零件开孔变化：未套料时直接更新；已套料未切割时重新排样；已切割时判断返修或重制；已装配时触发现场评审。不同状态不能用同一审批流程处理。

6.3 工艺知识数字化

需要把专家经验拆解为可执行规则：适用船型、材料、板厚、设备、坡口、方向、间距、热输入、检验方式和例外条件。规则应当可版本化、可测试、可解释，不宜只写在算法代码里。

6.4 动态智能套料

目标函数应从“最大材料利用率”扩展为：

综合成本 = 材料浪费 + 延期惩罚 + 设备时间 + 穿孔与能耗 + 分拣物流 + 质量风险 - 余料未来价值

大型船厂更需要多目标和跨批次优化；中型船厂可以先实现库存可信、余料优先和交付优先级。

6.5 设备、质量与能源反馈

每个NC任务应回传实际板材、程序版本、开始结束时间、暂停和报警、实际切割长度、穿孔次数、废品、返工与余料轮廓。质量系统应关联零件、设备、参数和操作者，才能判断问题来自设计、工艺、设备还是材料。

6.6 分段齐套与物流

套料不能只输出零件，还应输出托盘和交付关系。系统需要显示某分段缺哪些零件、缺件处于设计/采购/切割/返工哪个阶段，以及预计何时齐套。二维码、定位标签或视觉识别可用于减少找件和错配。

6.7 国产化与开放架构

国产化不只是替换CAD品牌，还要控制几何内核、工艺模型、后处理器、接口规范和制造数据。平台应支持标准API、事件消息、批量文件和离线模式，允许旧系统渐进接入。

6.8 信息安全与可靠性

船舶设计和生产数据具有较高敏感性。系统应支持厂内部署、最小权限、操作审计、程序签名、备份恢复和网络分区。设备网络中断时，现场仍需受控执行已批准任务，并在恢复后同步。

6.9 分层产品方案

产品层适用对象核心功能交付方式
套料核心单车间、中小船厂导入、排样、工艺、NC、余料单机或局域网
生产准备平台中大型船厂规则、版本、审批、多设备、托盘私有化部署
数字主线平台大型集团船厂PLM/ERP/MES/WMS集成、变更、追溯分阶段集成
智能优化层数据基础成熟的船厂动态套料、排程、质量和能耗优化在现有平台上增量建设

6.10 推荐的验证指标

  • 材料利用率及其按板厚、材质、船型的分布。
  • 完整板消耗、余料生成率、余料复用率和账实一致率。
  • 每100个零件的生产准备工时、人工调整次数和NC审核时间。
  • 分段齐套率、缺件等待时间和二次搬运次数。
  • 设计变更识别时间、旧程序拦截率和版本误用次数。
  • 设备OEE、空行程、穿孔次数、程序等待和报警时间。
  • 首次加工合格率、返工率、废品率和单位切割长度能耗。
  • 数据接口成功率、主数据完整率和追溯记录完整率。

后续核实工作

正式对外使用前，应补充船厂官网、公开招标、供应商案例、学术论文、专利、招聘信息和现场访谈证据。重点核验三家船厂当前的软件名称与版本、系统边界、设备品牌、接口方式、材料利用率基线、套料人工工时、余料管理方式、NC下发流程和设计变更处置流程。
